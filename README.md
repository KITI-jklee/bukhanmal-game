# 통일 워드게임 (innopost_game)

통일부 공공데이터를 활용한 북한말 학습 웹 게임. React + TypeScript + Vite.

## 실행

```bash
npm install
npm run dev
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 (기본 5173) |
| `npm run build` | 타입체크 + 프로덕션 빌드 |
| `npm run lint` | oxlint |
| `npm test` | 전체 프런트엔드 단위 테스트 |
| `npm run check:engine` | 산성비게임 엔진 테스트 |
| `npm run check:chosung` | 초성게임 엔진 테스트 |

## 구현 범위

| 화면 | 경로 | 상태 |
|---|---|---|
| 메인 | `/` | 완료 |
| 난이도 선택 | `/` 내 모달 | 완료 |
| 남북한말 산성비게임 | `/acid-rain?difficulty=보통` | 완료 |
| 게임 결과 | `/result` | 완료 |
| 랭킹 | `/ranking` | 완료 |
| 게임 방법 안내 | 게임 카드의 모달 | 완료 (두 게임 모두) |
| 북한말 초성게임 | `/chosung?difficulty=보통` | 완료 |

게임 방법은 별도 페이지를 두지 않는다. 규칙이 게임마다 완전히 다르기 때문에
한 페이지에 모으면 사용자가 자기 게임 규칙을 골라 읽어야 한다. 각 게임 카드의
"게임 방법 보기"가 해당 게임 규칙만 담은 모달을 연다(`GameGuideDialog`).

## 데이터

- `src/data/acidrain_pairs.json` — 남북한 단어쌍 500개 (쉬움 200 / 보통 180 / 어려움 120)
- `src/data/chosung_words.json` — 초성게임 문제 496개 (쉬움 200 / 보통 176 / 어려움 120)
- API 명세서 B-2 스키마를 그대로 따른다. 런타임에 외부 API를 호출하지 않는다(FR-DT-04).
- 데이터 갱신은 수집·정제 스크립트 재실행 후 이 파일을 교체하는 방식만 지원한다(FR-DT-05).

## 백엔드 (FastAPI)

`server/`에 FastAPI + SQLite 백엔드가 있다. API 명세서 C-1·C-2를 그대로
구현했고, 프런트엔드 `src/lib/rankingApi.ts`의 계약과 필드명이 1:1로
대응한다. 자세한 실행법·구조·확정 필요 항목은 [server/README.md](server/README.md)
참고.

```bash
cd server && uvicorn app.main:app --reload --port 8000   # 최초 1회 설치는 server/README.md 참고
```

점수 저장·랭킹 조회는 프런트엔드 `src/lib/rankingApi.ts` 한 곳에
격리되어 있다. 레포 루트에 `.env.local`을 두면 목업 대신 이 서버를 호출한다.

```bash
# innopost_game/.env.local
VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1
```

이 파일이 없으면(기본 상태) localStorage 목업으로 동작해, 서버를 안 띄워도
프런트엔드 작업이 막히지 않는다. 서버가 있는데도 명시적으로 목업을 쓰려면
`VITE_USE_MOCK=true`를 추가한다.

### 아직 SQLite인 이유

산성비게임 3단계는 무한 생존이라 진짜 "이론상 최대 점수"가 존재하지
않는다(초성게임은 계산 가능해 정확한 값을 뒀다 — `server/app/scoring_limits.py`).
운영 DB(PostgreSQL 등)가 정해지면 `DATABASE_URL` 환경변수만 바꾸면 되도록
저장소 계층을 SQLAlchemy 엔진 하나에만 의존하게 만들었다.

## 게임 규칙 검증

산성비게임 로직은 `src/game/AcidRainEngine.ts`에 React와 분리해 두었고,
`scripts/engine-check.ts`가 가상 시계로 게임 루프를 돌려 기획서 4장의 수치를 검증한다.

```bash
npm run check:engine
```

검증 항목: 스폰 간격·동시 출현 상한, 난이도별 기본점수, 콤보 배수(×1/×2/×3),
오답 처리, 시간정지 단어 출현·정지·점수 제외, 스테이지 전환(13개/18개),
스테이지3 가속(10개마다 -0.3초, 하한 3초), 방어 게이지 15%씩 감소·7회 게임오버,
일시정지, 동시 출제 중복 방지.

초성게임 로직도 같은 방식으로 `src/game/ChosungEngine.ts`에 분리했고,
`scripts/chosung-check.ts`가 기획서 3장의 수치를 검증한다.

```bash
npm run check:chosung
```

검증 항목: 한 판 10문제·중복 출제 방지, 힌트 단계별 기본점수(10·5·2),
힌트 공개 내용(남한말 표현 → 첫 글자), 힌트 사용 시 제한시간 불변,
하트 3개·오답 3회 0점 처리, 20초 시간 초과, 콤보 보너스(+2~+5 상한)와
초기화 조건(힌트 열람·오답), 난이도 배수(×1.0/×1.2/×1.5) 1회 적용,
공백 정규화·복수 정답·편집거리 1 미인정, 실제 데이터 유효성.

## 기획서와 다르게 적용한 부분

UI 시안의 문구 중 기획서와 충돌하는 두 가지를 기획서 기준으로 맞췄다.

| 위치 | 시안 문구 | 변경 내용 | 근거 |
|---|---|---|---|
| 난이도 모달 | "난이도가 높을수록 제한 시간이 짧아져요" | 난이도는 출제 단어·기본점수만 결정, 속도는 스테이지가 올림 | 상세기획서 4-2 |
| 랭킹 화면 | "이번 주 랭킹 / 시즌 08 · D-4" | 시즌·주간 리셋 없는 상시 누적 랭킹 | FR-RK-04 |
| 낙하 단어 | 단어 위 "북한말/남한말" 배지 | 배지 제거, 색으로만 구분 | 상세기획서 4-1 (7) |
| 산성비 화면 | 어두운 배경 | 서비스 전체와 같은 밝은 톤으로 변경 | 발주 확인 사항 |
| 카운트다운 | 3·2·1 | 5초. 그동안 입력 방향·시간정지 규칙을 함께 안내 | 발주 확인 사항 |
| 메인 하단 | "랭킹 보기 / 게임 방법 안내" 링크 | 헤더와 중복이라 제거 | 발주 확인 사항 |
| 헤더 메뉴 | 게임 / 랭킹 / 게임 방법 | 게임 / 랭킹 (게임 방법은 카드 모달로) | 발주 확인 사항 |
| 난이도 값 | `하` / `중` / `상` | **`쉬움` / `보통` / `어려움`** | 발주 확인 사항 |
| 닉네임 재입력 | 최초 1회만 입력, 이후 재입력 없음(FR-CM-10) | **매 게임 종료 시 다이얼로그를 띄우고 저장된 닉네임을 미리 채워 확인·수정 가능** | 발주 확인 사항 |

닉네임을 바꿔서 등록해도 **이미 랭킹에 올라간 과거 기록의 닉네임은 그대로 둔다**(재등록·재계산 없음).
바뀐 닉네임은 그 순간부터의 새 기본값이 된다. 이미 닉네임이 있는 사용자에게는
"다음에 하기"(건너뛰기) 버튼을 주지 않는다 — 확인·수정만 하는 상황이라 건너뛸
이유가 없다. 아직 닉네임이 없는 첫 사용자는 이전처럼 건너뛸 수 있다.

### 난이도 값 변경 (API 명세서 반영 필요)

표기뿐 아니라 **내부 값까지** 바꿨다. 따라서 아래가 함께 바뀌어야 한다.

| 대상 | 변경 내용 |
|---|---|
| `acidrain_pairs.json` · `chosung_words.json` | `difficulty` 필드 마이그레이션 완료 |
| API 명세서 C-1 `difficulty` | `"하"\|"중"\|"상"` → `"쉬움"\|"보통"\|"어려움"` |
| API 명세서 C-2 쿼리 `difficulty` | 위와 동일 |
| 백엔드 검증 로직 | 열거값 갱신 필요 |

`similarity`(낮음/보통/높음)는 별개 필드이므로 건드리지 않았다.
목업 랭킹 저장 키를 올려, 이전 난이도 값으로 저장된 기록 때문에 리더보드가
비어 보이는 일이 없게 했다.

낙하 단어에는 기획서대로 배지를 쓰지 않는다. 다만 초록(#0c6e54)과 진한 노랑(#f4b94b)은
적록색약에서 구분이 어려운 조합이라, 색에만 의존하지 않도록 **모서리 모양**을 함께 다르게 했다.
폭을 전혀 늘리지 않는 단서다.

| 종류 | 색 | 모양 |
|---|---|---|
| 북한말 | 초록 | 완전히 둥근 모서리 |
| 남한말 | 진한 노랑 | 각진 모서리 |
| 시간정지 | 빨강 | 각진 모서리 + 점선 테두리 + 점멸 |

메인 화면 카드 썸네일의 "북한말/남한말" 라벨은 게임 화면이 아니라 게임을 소개하는
장식 요소이므로 그대로 두었다.

## 반응형·입력 처리

- 낙하 위치를 픽셀이 아닌 **진행률(0~1)** 로 관리해 화면 크기가 바뀌어도 단어가 튀지 않는다(NFR-03).
- `visualViewport` + `ResizeObserver`로 `--viewport-height` / `--keyboard-inset`을 갱신해
  모바일 가상 키보드가 열려도 입력창이 가려지지 않는다(NFR-02).
- 한글 IME 조합 중에는 Enter 제출을 판정하지 않는다(FR-CM-06).
- 탭 이탈·앱 전환·화면 회전 시 자동 일시정지된다(FR-CM-05).

## 초성게임 데이터

`chosung_words_500_with_meanings.json`(실제 뜻풀이 포함본)을 **496개**로 정리해
`src/data/chosung_words.json`에 넣었다.

| 항목 | 처리 |
|---|---|
| `difficulty` | `하·중·상` → `쉬움·보통·어려움` |
| 한 글자 단어 | 4건 제외 (꼴·례·밸·뽈) — 초성이 1개뿐이라 퀴즈가 성립하지 않음 |
| `initials`·`length`·`first_letter` | 500건 모두 정확해 그대로 사용 |
| `category` | 데이터에는 유지하되 화면에는 쓰지 않는다 (상세기획서 3-3) |

검증 결과 이상 없음 — 뜻풀이 500건 전부 채워져 있고, 정답이나 남한말 대응어를
노출하는 항목이 없으며, 중복 뜻풀이도 없다(평균 26자).

### 이전 샘플에서 있었던 문제 (해결됨)

첫 샘플(`chosung_words_500_sample.json`)의 `meaning`은 500건 전부
`"남한말로 풀이하면 ‘근해’입니다."` 형태로 **1단계 힌트를 미리 노출**해
기획서 3-3의 10·5·2점 설계를 무너뜨렸다. 당시에는 힌트를 열기 전까지
남한말을 `○○`로 가리는 방식으로 대응했다.

실제 사전형 뜻풀이(`"육지에서 비교적 가까운 바다."`)로 교체되면서
기본 정보 → 1단계 힌트 → 2단계 힌트가 각각 다른 정보를 주게 되어
**가림 처리를 제거했다.** 부분 문자열 때문에 오히려 해로웠기 때문이기도 하다 —
`"골문"`의 `골`, `"행복한"`의 `복`처럼 남한말이 다른 단어 안에 들어 있으면
멀쩡한 뜻풀이를 `"○문"`, `"행○한"`으로 망가뜨린다.

초성이 같은 문제(쉬움 12그룹·보통 7그룹)도 뜻풀이가 모두 달라 구분된다.
가림 처리 시절 임시로 노출했던 분야 칩도 함께 제거했다.
